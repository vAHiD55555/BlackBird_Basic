# راه‌اندازی قدم‌به‌قدم با موبایل

## نگه‌داشتن اجرای فعلی

نسخهٔ قدیمی main.py که در میزبان شما کار می‌کند می‌تواند بدون تغییر ادامه بدهد. برای تحلیل، لازم نیست آن را متوقف کنید. فایل tools/analyze_prices.py مستقل است و می‌توانید فقط همان را برای اجرای آفلاین دانلود کنید.

## نصب نسخهٔ پوشه‌بندی‌شده در Botkeep یا میزبان مشابه

1. پیش از هر تغییر از main.py، prices.csv و monitor.log فعلی نسخهٔ پشتیبان بگیرید.
2. کد مخزن را از Code → Download ZIP دریافت و استخراج کنید.
3. محتویات پروژه را بارگذاری کنید، نه فقط main.py؛ پوشهٔ collector باید کنار آن باشد.
4. فقط هنگام جایگزینی برنامه، اجرای قبلی را متوقف کنید تا هم‌زمان دو نویسنده روی یک CSV کار نکنند.
5. فایل شروع را main.py و در صورت نیاز فرمان را python main.py بگذارید.
6. پروژه هیچ بستهٔ pip نیاز ندارد؛ requirements.txt عمداً فقط توضیح دارد. وابستگی‌های برنامه‌های دیگر را حذف نکنید.
7. قیمت‌ها به prices.csv در ریشهٔ پروژه افزوده می‌شوند؛ monitor.log نیز در همان محل است.
8. برای بررسی اتصال یک‌باره: python main.py --once

این نسخه وب‌سرور یا health endpoint ندارد. اگر میزبان الزام HTTP دارد، مناسب‌بودن این تنظیم باید جدا بررسی شود. این راهنما تأیید شرایط استفادهٔ میزبان برای محل اقامت شما نیست.

## اجرای تحلیل روی اندروید یا محیط دارای Python

Python 3.11 یا جدیدتر لازم است. پس از آماده‌کردن محیط، در پوشهٔ پروژه:

```sh
python tools/analyze_prices.py prices.csv --output reports/analysis.json
```

اگر تنها فایل تحلیل‌گر را دانلود کرده‌اید:

```sh
python analyze_prices.py prices.csv
```

مسیر و نام CSV را با فایل واقعی خود جایگزین کنید. هیچ کلید یا اتصال اینترنت برای تحلیل لازم نیست.

## اجرای دستی در GitHub

1. وارد مخزن شوید و بخش Actions را باز کنید.
2. در صورت نیاز Actions را فعال کنید.
3. گردش کار Analyze CSV manually را انتخاب کنید.
4. Run workflow را بزنید و متن CSV غیرحساس را همراه سطر عنوان در csv_text قرار دهید. ورودی باید چندخطی واقعی باشد، نه متن دارای کاراکترهای لفظی \\n.
5. اجرای کامل از مرورگر دسکتاپ/حالت Desktop site در موبایل ممکن است آسان‌تر باشد.
6. پس از پایان، نتیجهٔ تست و تحلیل را در لاگ و فایل data-quality-report را در Artifacts همان اجرا ببینید.

این روش برای فایل‌های کوچک است. اگر فرم موبایل ورودی چندخطی را درست حفظ نمی‌کند یا داده بزرگ است، اجرای محلی را استفاده کنید. CSV در تاریخچهٔ Git ثبت نمی‌شود، اما ورودی، لاگ و artifact را خصوصی فرض نکنید. هرگز کلید API، شناسهٔ حساب، موجودی شخصی یا اطلاعات کیف پول نگذارید.

این گردش کار collector را اجرا نمی‌کند، زمان‌بندی ندارد و از Botkeep داده دریافت نمی‌کند. اتصال خودکار و webhook هنوز پیاده‌سازی نشده‌اند.

## معنی نتیجه و خطاها

- کد خروج 0: فایل قابل تحلیل بوده؛ این به معنی بی‌نقص‌بودن داده یا سودآوری نیست.
- کد خروج 1: فایل پیدا نشد، عنوان ستون‌ها نادرست بود یا خواندن/نوشتن ناموفق بود.
- کد خروج 2: سطر نامعتبر وجود دارد یا فایل دادهٔ معتبر ندارد؛ ممکن است گزارش جزئی تولید شده باشد.
- gaps_over_330_seconds: فاصلهٔ بزرگ‌تر از 330 ثانیه با فرض دریافت اسمی هر 300 ثانیه. شمارش قطعی درخواست‌های ازدست‌رفته نیست.
- duplicate_source_extra_rows: زمان منبع تکراری؛ ممکن است معاملهٔ جدیدی در منبع رخ نداده باشد، نه الزاماً خطای برنامه.
- source_lag: اختلاف زمان منبع و سرور؛ تحت تأثیر ساعت‌هاست و تأخیر خالص شبکه نیست.
- min/max: کمینه و بیشینهٔ نمونه‌های دریافتی، نه سقف/کف همهٔ معاملات بازار.

## پشتیبان‌گیری و محدودیت‌ها

فایل CSV در حدود 5MiB با نام زمان‌دار آرشیو می‌شود؛ آرشیوها خودکار حذف نمی‌شوند. فضای دیسک و پشتیبان‌گیری بر عهدهٔ اپراتور است. لاگ چرخشی حداکثر دو نسخهٔ قدیمی را نگه می‌دارد. از پاک‌کردن یا بازنویسی فایل‌های برنامه‌های دیگر اجتناب کنید. پیغام HTTP 401، 403 یا 451 باعث توقف collector می‌شود؛ هیچ دورزدنی انجام نمی‌شود.
