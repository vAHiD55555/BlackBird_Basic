# راه‌اندازی قدم‌به‌قدم با موبایل

## نگه‌داشتن اجرای فعلی

سرور و فایل‌های قبلی را دست‌نخورده نگه دارید. برای پروژهٔ تازهٔ Botkeep از [بستهٔ مستقل](../deploy/botkeep/) و [راهنمای آپلود](../deploy/botkeep/README_FA.md) استفاده کنید: محتویات آن پوشه مستقیماً به ریشهٔ پروژهٔ تازه می‌رود. برای تحلیل، نیازی به توقف جمع‌آورنده نیست؛ tools/analyze_prices.py مستقل است. دو فرایند نباید روی یک CSV یا خروجی مشترک بنویسند.

## نصب نسخهٔ پوشه‌بندی‌شده در Botkeep یا میزبان مشابه

1. پیش از هر تغییر از main.py، prices.csv و monitor.log فعلی نسخهٔ پشتیبان بگیرید.
2. کد مخزن را از Code → Download ZIP دریافت و استخراج کنید.
3. اگر نسخهٔ ریشهٔ مخزن را انتخاب کرده‌اید، محتویات پروژه را بارگذاری کنید، نه فقط main.py؛ پوشهٔ collector باید کنار آن باشد. نسخهٔ deploy/botkeep/main.py مستقل است و collector نمی‌خواهد.
4. فقط هنگام جایگزینی برنامه، اجرای قبلی همان پروژه را متوقف کنید تا دو نویسنده روی یک CSV کار نکنند؛ سرور قدیمی مستقل را تغییر ندهید.
5. فایل شروع main.py و فرمان اختیاری python main.py --interval 60 است. پیش‌فرض 60 ثانیه است؛ --interval 30 نیز پذیرفته می‌شود. مقدار باید مثبت و محدود باشد.
6. Python 3.11+ و کتابخانهٔ استاندارد کافی است؛ requirements.txt فقط توضیح دارد. وابستگی‌های برنامه‌های دیگر را حذف نکنید. کلید، .env، کیف پول، معامله و مدل AI وجود ندارد.
7. قیمت‌ها در prices.csv و لاگ در monitor.log کنار نسخهٔ برنامه ذخیره می‌شوند؛ در نسخهٔ پوشه‌بندی‌شده، ریشهٔ مخزن. مسیر CSV با --output تغییر می‌کند؛ مسیر نسبی نسبت به پوشهٔ کاری است.
8. بررسی اتصال اختیاری: python main.py --once؛ یک بار شش جفت BTC-USD، ETH-USD، SOL-USD، XRP-USD، DOGE-USD و ADA-USD امتحان می‌شوند. موفقیت‌های جزئی ذخیره و شکست با کد خروج غیرصفر مشخص می‌شود. ممنوعیت دسترسی کل اجرا را زودتر متوقف می‌کند.

این نسخه وب‌سرور، پورت شنونده یا health endpoint ندارد. ممکن است میزبان الزام HTTP یا محدودیت اجرای پس‌زمینه داشته باشد؛ سازگاری، هزینه و سیاست فعلی Botkeep و پذیرش Coinbase برای موقعیت شما تأیید نشده است. API عمومی فعلی به کلید نیاز ندارد؛ رایگان‌بودن میزبانی یا تداوم دسترسی تضمین نشده است.

## چرخه و خطاهای جمع‌آورنده

شش درخواست ترتیبی‌اند، نه شش فرایند موازی. زمان پردازش از فاصلهٔ چرخه کم می‌شود؛ با monotonic زمان‌بندی می‌شود و در تأخیر زیاد چرخه‌ها هم‌پوشانی ندارند و هجوم جبرانی نداریم. فاصلهٔ دقیق تضمین نیست. قیمت و زمان هر پاسخ اعتبارسنجی می‌شود؛ قیمت قبلی، دادهٔ ساختگی یا دارایی جایگزین برای شکست تولید نمی‌شود. پشتیبانی زندهٔ هر جفت بررسی نشده است.

- خطای یک جفت مانع حفظ موفقیت بقیه نیست؛ در اجرای مداوم خطای عادی تا چرخهٔ بعد دوباره امتحان نمی‌شود.
- HTTP 401، 403 یا 451: توقف کامل بدون دورزدن.
- HTTP 404: جفت با نام و کد خطا لاگ و تا پایان همان اجرا غیرفعال می‌شود؛ اگر همه غیرفعال شوند برنامه متوقف می‌شود.
- HTTP 429: مکث سراسری حداقل 60 ثانیه و رعایت Retry-After عددی یا تاریخی در صورت معتبر بودن. در حالت مداوم چرخهٔ جاری قطع می‌شود؛ در --once پیش از درخواست بعدی مکث می‌شود. تأخیر طولانی ممکن است باعث timeout گردش کار GitHub شود.
- --once: موفقیت کامل کد 0، شکست جزئی کد 1؛ رکوردهای موفق قبلی پاک نمی‌شوند.

## اجرای تحلیل روی اندروید یا محیط دارای Python

```sh
python tools/analyze_prices.py prices.csv --expected-interval 60 --output reports/analysis.json
# فایل با نرخ 30 ثانیه
python tools/analyze_prices.py prices.csv --expected-interval 30
# فایل قدیمی پنج‌دقیقه‌ای
python tools/analyze_prices.py old-prices.csv --expected-interval 300
# همهٔ تست‌های آفلاین
python -m unittest discover -s tests -v
```

اگر فقط تحلیل‌گر را دانلود کرده‌اید، tools/ را از فرمان حذف کنید. مسیر CSV را با فایل واقعی جایگزین کنید؛ تحلیل کلید یا اینترنت نمی‌خواهد. برای تغییر نرخ فایل تازه بسازید، مثلاً python main.py --interval 60 --output prices-60s.csv. دوره‌های دارای نرخ متفاوت را جدا تحلیل کنید.

گزارش برای هر جفت حاضر در فایل جداست و فقدان جفتی که اصلاً رکورد ندارد را کشف نمی‌کند. JSON اکنون expected_interval_seconds و gap_threshold_seconds دارد؛ gaps_over_threshold_seconds جایگزین gaps_over_330_seconds شده است. آستانه 1.1 برابر فاصلهٔ انتخابی است: 66، 33 یا 330 ثانیه. شمارش فاصله‌ها شمارش قطعی درخواست ازدست‌رفته نیست. CSV همان چهار ستون قبلی را دارد.

## اجرای دستی در GitHub

1. Actions → Analyze CSV manually → Run workflow؛ شاخهٔ master را انتخاب کنید.
2. expected_interval را 60، 30 یا برای CSV قدیمی 300 بگذارید.
3. csv_text خالی: ابتدا تست‌های آفلاین، سپس یک چرخهٔ واقعی شش جفت با خود جمع‌آورنده اجرا می‌شود. این فقط بررسی اتصال است، نه تداوم، فشار بازار، پیش‌بینی نوسان یا سودآوری. خطا واقعی ثبت و موفقیت‌های جزئی تحلیل می‌شوند؛ شکست مرحلهٔ دریافت همچنان شکست اجرا باقی می‌ماند.
4. csv_text غیرخالی: CSV کوچک غیرحساس همراه سطر عنوان؛ خط واقعی یا جداکنندهٔ لفظی \\n پذیرفته می‌شود. هیچ درخواست قیمت در این حالت ارسال نمی‌شود. Desktop site مرورگر ممکن است کار با فرم را آسان‌تر کند.
5. پس از پایان، Summary و مرحله‌ها را باز کنید. artifact با نام data-quality-report و شناسهٔ اجرا تا 7 روز نگه‌داری می‌شود.

### خروجی و حریم خصوصی

- reports/tests.txt: خروجی واقعی تست‌ها
- reports/mode.txt: روش اجرا
- reports/analysis.json و analysis.txt: گزارش در صورت تولید موفق، حتی از موفقیت‌های جزئی
- reports/connection.txt: لاگ چرخهٔ واقعی، فقط در حالت ورودی خالی
- Summary: تعداد رکورد هر جفت و فاصله‌های غیرعادی

ورودی، لاگ و artifact را خصوصی فرض نکنید. CSV در تاریخچهٔ Git ثبت نمی‌شود، ولی قیمت و زمان در گزارش دیده می‌شود؛ اطلاعات حساب، کیف پول و کلید وارد نکنید. فرم برای داده‌های کوچک است؛ برای دادهٔ بزرگ تحلیل محلی مناسب‌تر است. گردش کار زمان‌بندی ندارد، به Botkeep وصل نیست، داده را به مخزن push نمی‌کند و خودکار اجرا نمی‌شود. افزودن تست و workflow به معنی اجرای موفق نیست؛ این تغییرات در این گفتگو اجرا یا روی میزبان تست زنده نشده‌اند.

## معنی نتیجهٔ تحلیل

- خروج 0: فایل قابل تحلیل؛ نه تضمین کیفیت کامل یا سود.
- خروج 1: مسیر، عنوان ستون‌ها، فاصلهٔ نامعتبر یا خطای خواندن/نوشتن.
- خروج 2: سطر نامعتبر یا نبود رکورد معتبر؛ ممکن است گزارش جزئی موجود باشد.
- duplicate_source_extra_rows: زمان منبع تکراری؛ شاید معاملهٔ تازه‌ای رخ نداده، نه الزاماً خطای برنامه.
- source_lag: اختلاف ساعت منبع و دریافت، نه تأخیر خالص شبکه.
- min/max: کمینه و بیشینهٔ نمونه‌ها، نه سقف و کف کل معاملات بازار.

## پشتیبان‌گیری و محدودیت‌ها

CSV در حدود 5MiB با نام زمان‌دار آرشیو می‌شود؛ آرشیوها خودکار حذف نمی‌شوند. لاگ چرخشی دو نسخهٔ قدیمی نگه می‌دارد. prices*.csv و monitor.log* را مرتب پشتیبان بگیرید و فضای دیسک و ماندگاری پس از restart را بررسی کنید. دادهٔ واقعی و فایل برنامه‌های دیگر را در مخزن عمومی منتشر یا بازنویسی نکنید. این داده کندل، عمق بازار یا قیمت تضمین‌شدهٔ اجرای سفارش نیست؛ هیچ معامله، کارمزد یا سود استراتژی شبیه‌سازی نشده است.
